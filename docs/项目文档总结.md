**四条最重要的结论**

1. **三层链路是真的跑通了**，不是 PPT 工程：后端 19 个接口有实现 + 96 个测试用例；Agent 有完整的 `thinking → sql → answer → chart → done` SSE 事件链和 SQL 安全层；前端 19 个接口全部有调用方。
2. **唯一的不稳定点是“本地 → 远端 MySQL”连接**：`error-log.md` 15:07 的 13 个 `ApplicationContext` Error、`error2.md` 17:20 的 `Communications link failure` 是同一根因；但 **15:16 的全量测试 96/96 全绿**（含 12 个连真实库的集成用例）。同一配置两种结果 → 远端库/网络抖动，而不是代码缺陷。本机建库可彻底摆脱该依赖。
3. **数据基线存在漂移**：仓库里 `data/out/orders.csv` 是 **2017 全年** Olist 数据，但 `DashboardEndpointsTests` 的注释和 `docs/前端运行说明.md` 的验收数字（KPI ¥26,438,041.00、订单 2,828 条）都按 **2026 年**口径写。两者不是同一份数据，任何“验收通过”的结论都要先统一数据基线再复验。
4. **文档与代码有若干对不上的点**（DB 主机地址三处不一致、mock 行数、课程设计根目录与启动脚本、文档日期），已在第 12 章集中列出，避免答辩时被追问。

## 1. 项目概述

ES（E-commerce Sales Dashboard / ESDID）面向“电商运营 + 数据分析”场景，交付三件套：

1. **数据看板**：基于 MySQL 订单表（`ecommerce` 库），用 Vue3 + ECharts 展示全局 KPI、销售趋势与对比、商品 TOP10、品类帕累托、客单价分布、24 小时时段、用户与支付、目标达成率、促销效果、RFM 分层、地域分布、订单明细与 CSV 导入导出，共 **19 个 REST 接口（A1–A19）**。
2. **自然语言查数 Agent**：用户用中文提问（如“上个月手机品类销售额环比变化多少”），Python 侧完成：理解问题 → 检索 SQL 模板（few-shot）→ 生成 SQL（工具循环自纠错，最多 3 轮）→ sqlglot 安全校验 → 只读执行 → 结果解读 → 返回结论 + ECharts 图表，全程 SSE 流式。
3. **工程与部署材料**：5 张表的 schema、Olist 真实数据 ETL、Docker Compose 三容器部署、Nginx 反向代理、打包成 `agent.exe` 的独立部署方案、12 张角色的 `agent-team/` 多 Agent 实验。

**规模与使用假设**：个人 / 小团队学习项目，日 PV 很低；所有设计取舍（单机 MySQL、无消息队列、Caffeine 本地缓存、异步导入用线程池）都服从这个前提。

**一句话讲清“为什么做这个项目”**：把“看板”这种 CRUD + 聚合的常规作业，往上叠一层 Text-to-SQL，用真实数据、真实部署、真实报错把课设做成能讲 20 分钟的作品。

## 4. 数据链路（最容易被追问的部分）

### 4.1 数据从哪来

- 原始数据：Kaggle **Brazilian E-Commerce Public Dataset by Olist**（2016-09 ~ 2018-10，**共 99,441 单**）。
- 转换脚本：`tools/olist-etl.mjs`，零依赖，`node tools/olist-etl.mjs --source data/olist --out data/out --ddl`。
- 过滤后保留 **44,375 单**（剔除 canceled / unavailable 等无效状态）。

### 4.2 ETL 口径（答辩必被问）

| 项 | 规则 |
|---|---|
| 货币 | BRL → CNY，汇率 `1.45`（`--rate` 可调） |
| 有效状态 | `delivered / shipped / invoiced / processing / approved` |
| 品类 | 原始英文品类归并为 6 大类（手机/电脑/服饰/美妆/食品/家电）+「其他」，`--category-mode original` 可保留原名 |
| 支付方式 | `credit_card/debit_card → card`、`boleto → alipay`、`voucher → wechat` |
| 用户类型 | 按首单时间划分 new / old |
| 地域 | `customer_state` 映射中国省份看板口径（`--region cn`） |
| 商品名 | 品类 + 商品 ID 前 6 位构造（如 `服饰 F5D8F4`），保证可展示、可聚合 |
| 目标额 | 按「月 × 品类」用实际 GMV 结构反推，达成率落在 **75%~115%**，共 **96 条**（12 个月 × 8 品类） |

### 5.4 关键实现机制

- **统一响应**：`Result<T>{code,message,data}`，`ErrorCode` 枚举 + 全局异常处理器；参数校验用 Jakarta Validation，错误码统一。
- **缓存**：`CacheConfig` 用 Caffeine 裸实例（不用 Spring Cache 抽象，便于单测），两个 Bean：`categoryListCache`、`targetListCache`。
- **异步导入**：`ImportTaskExecutor` + `AsyncConfig.importExecutor` 线程池（拒绝策略 `CallerRunsPolicy`），批量 500，错误明细上限 500 行；任务状态 PROCESSING → SUCCESS/PARTIAL/FAILED。
- **CSV 导出**：流式写 `HttpServletResponse`，`Content-Disposition` 带 `orders_yyyyMMdd_yyyyMMdd.csv`，BOM 处理 Excel 中文乱码。
- **分页**：PageHelper，`page/size` 上限保护。
- **访问日志**：`AccessLogFilter`（uri/method/status/cost）。
- **定时任务**：`DailySummaryJob` `@Scheduled(cron = "${dashboard.schedule.daily-summary-cron}")`，支持传入日期补跑 `rebuild(LocalDate)`。
- **CORS**：`CorsConfig` + `CorsProperties`（YAML 列表必须 `@ConfigurationProperties` 绑定，`@Value` 解不了列表）。
- **数据源**：HikariCP `maximum-pool-size 10 / minimum-idle 2 / connection-timeout 30000`；`spring.sql.init.mode=always` + `classpath:db/schema.sql`（`continue-on-error: false`）。

### 7.3 双链路（核心亮点，答辩重点）

1. 用户问题 → 前端 POST `/chat`（SSE）→ 编排器取 Redis 会话历史（支持“那环比呢”这类指代）→ 向量检索 Top-4 模板作 few-shot。
2. **Agent1** 生成 SQL，工具循环可直接执行工具自纠错（最多 3 轮）。
3. `sql_safety` 用 sqlglot 解析：非 SELECT 拒绝、表/字段不在白名单拒绝、自动补 `LIMIT`（`MAX_ROWS=1000`）。
4. 只读账号执行（`QUERY_TIMEOUT=10s`，结果缓存 `SQL_CACHE_TTL=300`，限流 `RATE_LIMIT=30`）。
5. **Agent2** 解读结果 → `{answer, charts}`，前端渲染 ECharts。

- **数据哪来的？** Olist 真实订单 99,441 → 有效 44,375，汇率 1.45，2026 年时间轴是文档示例口径（见 §4.5 待统一）。

- **Milvus 呢？** 镜像 403 放弃，`vector_store` 自动降级本地 256 维检索，接口不变。
- **测试都过了吗？** 最近一次全量 **96/96 通过**（surefire 15:16）；但其中 13 个（12 集成 + 1 上下文）依赖远端 MySQL，15:07 与 17:20 两次因连接超时整批红，根因在 `error2.md`，非代码。答辩时可直接展示 surefire 报告。

## 附录 C：术语

- **A1–A19**：接口编号，沿用 `docs/后端开发文档.md`。
- **双 Agent**：Agent1 生成 SQL（工具循环自纠错），Agent2 解读结果（结论 + 图表）。
- **ISO 周**：`%x-%v`，跨年周归属周四所在年，避免“2026-W53”串年。
- **RFM**：Recency / Frequency / Monetary 三层分位，8 个分层。
- **帕累托**：按销售额降序累计占比，画 80% 参考线。
- **促销拉动率**：`(活动期GMV − 非活动期GMV) / 活动期GMV`，不是“促销占比”。
- **降级**：Milvus 不可达时切本地 256 维向量检索；LLM 无 Key 时切 Mock 生成器/分析师。
