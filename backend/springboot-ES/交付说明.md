## 三、关键口径（与文档逐条对齐）

1. **时间条件左闭右开**：`order_time >= startDate AND order_time < DATE_ADD(endDate, INTERVAL 1 DAY)`。
2. **日期缺省**：统计接口默认最近 30 天（A16 为 90 天）；`startDate > endDate` → 400；格式非 `yyyy-MM-dd` → 400。
3. **比率**：统一 0~1 的 4 位小数，分母为 0 或数据缺失一律返回 `null`（绝不返回 0/Infinity），并保证 `null` 字段**出现在 JSON 中**（`spring.jackson.default-property-inclusion=always`），前端据此显示「无对比数据」。
4. **空数据**：数组 `[]`、数值 `0`、比率 `null`；A10 固定 24 元素、A8 固定 6 区间、A9 累计末位 1。
5. **SQL 注入防护**：`sort`/`rankBy`/`granularity` 全部白名单化，`${}` 只用于白名单枚举产生的常量（排序列、排序方向、ISO 周表达式），用户输入一律 `#{}` 预编译。
6. **导入事务**：整个导入在**一个事务**内完成（清空 + 批量写入 500 行/批），文件级/数据库级异常 → 整体回滚并置 `FAILED`；行级校验错误**不中断**导入，逐行记入 `import_task_error`（`row` 为含表头的 CSV 行号）。
7. **导入状态机**（文档 §6.1）：`SUCCESS`（errorRows=0）/ `PARTIAL`（validRows>0 且 errorRows>0）/ `FAILED`（validRows=0 或文件级异常）。
8. **缓存一致性**：导入成功后主动失效 A1/A13 缓存，看板立即反映新数据。
9. **MyBatis-Plus 的分工**：**CRUD 用 MP，统计用 XML 原生 SQL**。MP 用于 `BaseMapper`（5 个 Mapper）、`ServiceImpl`/`IService`、`Wrappers.lambdaQuery`（如 A19 按 `taskId` 查任务）、实体注解（`@TableName`/`@TableId(IdType.AUTO)`，如 A18 `importTaskMapper.insert(task)`）；而 A2~A11/A13~A17 的全部聚合查询（`SUM`/`COUNT(DISTINCT)`/`CASE WHEN` 分桶/窗口函数/`DATE_FORMAT`/`HOUR()`/`GROUP BY`）写在 `resources/mapper/*.xml`，原因：① 文档 §A2 明确要求 A2 用手写 `COUNT(*)` + `LIMIT`，禁用 `selectPage`；② 这类分析型 SQL 用 Wrapper 表达会退化成字符串拼接，可读性与可调优性更差；③ 全部 SQL 集中在 XML，口径可按文档逐条比对。因此**未注册 MP 分页插件**（无 `selectPage` 使用点），详见 §五-19。

## 五、与《后端开发文档》的差异、自行决策与原因（重点）

| # | 项 | 文档 | 实际实现 | 原因 |
|---|---|---|---|---|
| 1 | 技术栈版本 | JDK 17 + Spring Boot 3.2 | **沿用工程现状：JDK 25 + Spring Boot 4.0.8** | 需求明确「沿用已有工程结构、依赖管理，不推倒重建」；文档示例中的 `javax/jakarta`、自动配置类名在 Boot 4 下有差异，已逐一适配 |
| 2 | JSON 日期格式 | 建议用 `Jackson2ObjectMapperBuilderCustomizer`/`JavaTimeModule`（§8.1） | 删除 `JacksonConfig`，改用字段级 `@JsonFormat(pattern="yyyy-MM-dd HH:mm:ss")` + `spring.jackson.*` 配置 | Boot 4 使用 **Jackson 3**（`tools.jackson`），文档中的 Jackson 2 定制器类已不存在（启动即编译失败）；字段级注解更精确且无需绑定框架内部 API |
| 3 | CORS 配置 | §8.2 用 `@Value("${dashboard.cors.allowed-origins}")` 注入列表 | `@ConfigurationProperties(prefix="dashboard.cors")` | `@Value` **无法解析 YAML 列表**，会抛 `PlaceholderResolutionException` 导致启动失败（已验证） |
| 4 | 包结构 | `dto/request`、`dto/vo`、`entity`、`mapper`（§1.2 示意） | `domain/dto`、`domain/vo`、`domain/po` | 沿用现有工程的 `domain` 分包约定，避免与既有代码冲突；分层与职责与文档一致 |
| 5 | 鉴权 | 文档无鉴权章节 | **未实现登录/鉴权** | 文档未定义鉴权方式，前端请求也不携带 token/凭证；`jjwt` 依赖保留但未使用，后续如需鉴权可按文档补充 |

| 19 | MP 分页插件 | §8.4 要求注册 `MybatisPlusInterceptor + PaginationInnerInterceptor(DbType.MYSQL)` | **未注册分页插件**；MyBatis-Plus 本身照常使用（`BaseMapper` / `ServiceImpl` / `Wrappers` / 实体注解，见 §三-9） | §A2 明确要求「`total` 用 `SELECT COUNT(*)`，`records` 用同条件 + `ORDER BY` + `LIMIT`，**不要用 MP 的 `selectPage` 拼 count 优化**」。全工程无一处 `selectPage`/`Page<>`，注册分页插件即为死配置；且 MP 3.5.9+ 已把 `PaginationInnerInterceptor` 拆到独立模块 `mybatis-plus-jsqlparser`，当前类路径**未**引入该模块（工程里的 `jsqlparser:4.7` 来自 pagehelper，与 MP 无关），注册它等于为无用配置新增依赖。按 §A2 这一更具体条款实现，故保留差异并在此标注 |

## 六、文档自身存在的不一致（已按文档主体口径实现，并在此标注）

以下是开发中发现的、文档内部相互矛盾或与事实不符之处。处理原则：**以文档的显式算法/主体口径为准**，并在此如实说明影响面。

| # | 位置 | 不一致点 | 实际处理与影响 |
|---|---|---|---|
| 1 | §A7 步骤 2「按桶序号对齐（两段长度相同、粒度相同）」 vs §10.1 用例「`2026-03-01~2026-03-31` → 对比期 `2026-01-29~2026-02-28`」 | 对比期按**自然日等长**（31 天）算出后，其端点会落在月中：`granularity=month` 时对比期含「2026-01 的部分桶 + 2026-02」两个桶，与本期「2026-03」一个桶**长度不等**，无法严格一一对应 | 严格实现文档 §A7 步骤 2 的桶序号对齐（第 i 桶对第 i 桶）。**`granularity=day`（默认、前端趋势图主用）时两段桶数完全相同，口径完全正确**；`week/month` 且区间不是整月/整周时，对比期的部分桶会被当作第 0 桶参与计算——这是文档两条规则在粗粒度下无法同时成立的必然结果，已用单测固定当前行为（`trend_monthGranularity_partialCompareBucketsAreAlignedByIndex`） |
| 2 | §10.1「A5 周粒度跨年 → period 形如 `2025-W53`/`2026-W01`」 | 事实性错误：2025 年只有 52 个 ISO 周（2025-12-28 = `2025-W52`，2025-12-29 = `2026-W01`）；真正的 W53 出现在 `2026-W53`（2026-12-28~2027-01-03） | 实现按真实 ISO 周 `DATE_FORMAT(order_time,'%x-W%v')`，跨年不串年；测试用真实周序（含 `2026-W53`/`2027-W01` 边界）验证 |
| 3 | §8.1/§8.2 示例代码 | `@Value("${dashboard.cors.allowed-origins}")` 无法注入 YAML 列表（会启动失败）；Jackson 2 的 `Jackson2ObjectMapperBuilderCustomizer` 在 Boot 4 已不存在 | 已分别改为 `@ConfigurationProperties` 与字段级 `@JsonFormat`（见 §五-2、§五-3） |
| 4 | §A18 表格「列数 ≠ 10 → 400」 vs §7/ETL 文档的 10 列定义 | 该 10 列**不含 `promoFlag`/`region`**，而 A2/A15/A17 依赖这两个字段 | 按文档实现（导入后 `promo_flag=0`、`region=NULL`）；演示顺序建议见 §七-2 |
| 5 | §4.5「金额字段两位小数」 vs §A14 备注「`dailyNeeded = 0`」 | 0 的标度未明确（`0` 还是 `0.00`） | 统一按 §4.5 输出两位小数（`0.00`），已修正 `dailyNeeded`、`targetAmount`、A8 缺失区间的 `sales` |

# 3) 接口文档
#    Knife4j:  http://localhost:8080/doc.html     （4 个分组：01-订单与统计 / 02-销售目标 / 03-用户分析 / 04-基础数据）

**演示时必须注意两点：**

1. **数据区间**：`data/out/init-data.sql` 是 **2017 全年**数据，而前端默认查「最近 30 天」（今天）。首次打开页面会因无数据而全空——请在页面上把日期范围选为 **2017 年内**（例如 `2017-01-01 ~ 2017-12-31`、双 11 活动用 `2017-11-01 ~ 2017-11-11`、目标达成用 `periodValue=2017-06`）。
2. **导入演示顺序**：A18 用的 CSV 是 10 列（不含 `promoFlag`/`region`），覆盖导入后 `promo_flag/region` 会丢失，A15/A17 将无数据。建议：先看完整看板 → 再演示导入（导出一个小文件再回传，或用 `data/out/orders.csv` 覆盖导入）→ 演示完如需完整数据，重新执行第 1 步的 `init-data.sql` 灌数。
