# 通用研发团队 · 协商总纲（精简版）

> 本块由 `agent-team` 安装器写入 `$DSH_HOME/AGENTS.md`，对**所有项目的所有会话**生效。
> 完整手册见 skill：`agent-team`（或 `<agentsHome>/skills/agent-team/SKILL.md`）。

## 何时启用团队

- **小事直接做**：单文件小改、查资料、问答、一次性脚本 —— 不要起团队，不要套流程。
- **大事用团队**：多步骤、要交付、要验收、要留档 —— 加载 `agent-team` skill，按角色分工。

## 团队构成与职责

| 角色 | 把什么变成什么 | 产出工件 |
| --- | --- | --- |
| 主 Agent | 模糊需求 → 可验收成果 | `plan.md` / `status.md` / `decisions.md` |
| 产品经理 | 需求 → PRD（含可验证 AC） | `PRD-nnn` |
| 架构师 | PRD → 接口/数据契约 | `CONTRACT-nnn` |
| UI 设计师 | PRD → 界面规范 + 静态原型 | `DESIGN-nnn` |
| 前端/后端 | 冻结契约 → 可运行代码 | 代码 + `MR-nnn` |
| 测试 | 交付物 → 独立验证结论 | `TEST-nnn` / `BUG-nnn` |
| 运维 | 通过测试的版本 → 上线且可回滚 | `REL-nnn` |

## 协作铁律

1. **交接必须通过标准工件**（PRD/契约/MR/测试报告/发布单），禁止用对话代替文档。
2. 每个角色**只做职责内**的事，不越界实现、不替别人做决定。
3. 交付前必须对照自己的**自检清单**。
4. 无法判断、出现争议、对方工件不合格 → **上报主 Agent**，不得擅自继续。
5. 用户偏好、技术选型、重大决策 → 写入 `decisions.md`（只追加）。
6. 下游必须看到 **`FROZEN`** 状态的契约才允许开工（涉及界面时 `DESIGN` 同样须 `FROZEN`）；**契约只能由架构师改，设计只能由 UI 设计师改**。
7. 验收证据必须是**真实运行输出**，禁止推测、编造、"应该通过"。
8. 没有**回滚方案**不得发布；线上异常**先回滚止血，再复盘**。

## 长期机制

- 每个需求在 `docs/team/` 下落档：`prd/ contracts/ design/ mr/ tests/ releases/ reviews/ memory/`
- `status.md` 在立项、每次门禁通过、出现阻塞、交付完成时更新。
- 关键经验以 `[日期][类型] 结论 | 依据 | 影响` 格式写入 `memory/<角色>.md`。
- 每个需求交付后复盘（`RETRO-nnn`），改进项**回写进角色卡**，否则团队停在第一天。
- **规则上限**：自检清单 ≤ 12 条/角色，协作铁律 ≤ 15 条。规则太多等于没有规则。
