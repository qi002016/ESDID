# 通用研发团队（agent-team）

这是一套**跨项目复用**的团队提示词资产。它把「模糊需求」变成「可交付、可验收的成果」，并由**标准工件**在角色之间交接，而不是靠对话。

## 第一步：先判断要不要起团队

| 情况 | 处理 |
| --- | --- |
| 改一行、修个错别字、查个资料、回答一个问题 | **不要**用本框架，直接做 |
| 单个文件的明确小改 | 直接做，不必召唤角色 |
| 多步骤、要交付、要验收、要留档 | **用本框架** |

不要为了「显得规范」而给小事套流程——**流程的成本必须小于返工的成本**。

## 第二步：装载顺序（按下表依次读，不要一次全读）

| 顺序 | 文件 | 谁读 |
| --- | --- | --- |
| 1 | `00-团队总纲.md` | **所有角色**（共同语言与铁律） |
| 2 | `09-升级矩阵与决策权.md` | 所有角色（谁能拍板、争议找谁） |
| 3 | `10-工件规范.md` | 所有角色（路径、命名、字段、长度） |
| 4 | `01-主Agent.md` | 主 Agent |
| 5 | `02-产品经理.md` … `07-运维工程师.md`、`12-UI设计师.md` | 对应角色**只读自己那张卡** |
| 6 | `08-长期机制.md` | 主 Agent + 需要写记忆的角色 |
| 7 | `11-角色卡骨架.md` | 需要新增角色时 |

**关键**：每个角色只加载自己那张卡 + 前三份公共文件。全量加载会浪费上下文并让职责模糊。

## 第三步：项目落地（每个新项目做一次）

1. 在项目里建 `docs/team/`，从 `templates/` 复制以下文件并按项目填写：
   - `config.md`（**必填**：可写范围、命令、端口、红线）
   - `plan.md`、`status.md`、`decisions.md`
2. 建子目录：`prd/ contracts/ design/ mr/ tests/ releases/ reviews/ memory/`
3. 把 `{{项目名}}` 替换为真实项目名。
4. 主 Agent 从 `01-主Agent.md` 的 G0 流程开始执行。

## 平台适配

- DeepSeek Harness（DSH）：读 `adapters/DSH.md`，里面有全局安装方式、skill 发现路径与 `$DSH_HOME/AGENTS.md` 注入规则。
- 其他平台（Claude Code / Cursor / 自建 Agent）：把 `00-团队总纲.md` 注入 system prompt 或 `AGENTS.md`，角色卡按需注入对应角色。

## 单文件版

`全部提示词.md` 是全部内容拼接而成的单文件版，适合无法按需加载文件、只能贴一段提示词的场景（如网页版对话框）。**能按需加载时不要用它**——它会一次性吃掉全部上下文。

## 铁律速记

1. 交接必须通过标准工件，禁止用对话代替文档。
2. 每个角色只做职责内的事。
3. 交付前对照自己的自检清单。
4. 无法判断、有争议、对方工件不合格 → 上报主 Agent，不得擅自继续。
5. 用户偏好、技术选型、重大决策 → 写入 `decisions.md`。
6. **下游看到 `FROZEN` 契约才允许开工**；涉及界面时 `DESIGN` 也须 `FROZEN`。契约只能由架构师改，设计只能由 UI 设计师改。
7. 验收证据必须是**真实输出**，禁止推测或编造。
